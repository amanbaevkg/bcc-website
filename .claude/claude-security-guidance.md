# Security guidance for bcc-web

Business Center Capellen website: Next.js 16 (App Router) with Payload CMS 3 inside the same app,
SQLite in /data, uploads on disk, a public contact form. Production runs as one Docker container
behind a TLS reverse proxy. Review changes against these rules.

## Never weaken

- Payload `csrf: [SITE_URL]` and `serverURL` (payload.config.ts). A 403 in the admin means
  SITE_URL is wrong on the server; never add origins, wildcards or remove the check to "fix" it.
- Auth cookie settings in Users.ts (HttpOnly, SameSite=Lax, Secure on https, 8 h expiry,
  login attempt limit). Do not lengthen sessions or relax lockout.
- The content security policy and security headers (proxy.ts / next.config.ts).
- The start checks: production refuses to run without an admin account, and warns (with
  SITE_ENV=production: refuses) when SITE_URL is not the public https address.

## Payload access

- Every collection and global must declare `access`. Admin data (`read`) is for signed-in users
  only; public pages read through the local API on the server. Only `media` files are public.
- Roles: `admin` manages users and legal pages; editors edit content and their own account only
  (`adminOrSelf`). The `role` field may only be set by admins (`isAdminField`).
- Local API calls with `overrideAccess: true` are allowed only in server code that never takes
  a document id, query or locale straight from a request.

## Contact form and API routes

- All input is validated on the server with the zod schema (lib/contact/schema.ts); the answers
  must be in the admin's lists. The browser check is only for convenience.
- No line breaks in values that end up in e-mail headers (subject, reply-to); quote display names.
- Keep the same-origin check, size limit, honeypot, minimum time, rate limit (last
  X-Forwarded-For entry only) and optional Turnstile check.
- E-mail HTML must escape every visitor value.

## Content and rendering

- No `dangerouslySetInnerHTML` with editor or visitor content. Rich text is rendered from the
  Lexical tree; links go through safeHref (no `javascript:`, `//host`, `/\host`).
- Uploads: images and video only (mimeType filters); never serve files from outside
  PAYLOAD_MEDIA_DIR; keep file names generated by Payload.

## Secrets and data

- Secrets (PAYLOAD_SECRET, SMTP/Resend/Postmark keys, Turnstile, Upstash) come only from
  environment variables; never in code, tests, logs, error messages or the browser bundle
  (no NEXT_PUBLIC_ prefix for secrets).
- Do not log visitors' e-mail addresses, messages or IP addresses beyond what is needed.
- Production must not expose stack traces, debug pages, source maps with secrets, or the
  Payload GraphQL playground.
- Never change PAYLOAD_SECRET, the database in /data, or Docker volumes.

## Dependencies and Docker

- Prefer upgrading a vulnerable dependency over overriding it; scoped pnpm overrides only.
- The image runs as a non-root user, exposes only port 3000, and keeps /data as a volume.
